# Мини-мессенджер — десктоп-клиент (Windows)

Ростер контактов + отдельные окна чатов, как в Psi, в современном дизайне (тёмная/светлая тема).
Работает в фоне и в трее, с ролями, отделами, рассылками и статусами присутствия.

## Важно: единственный сервер проекта

Раньше в `desktop-client/` лежала ещё одна копия `server.js` — из-за этого доработки (загрузка
файлов) какое-то время попадали не в тот файл, и рабочий сервер их не видел. Больше такой копии
нет. **Единственный сервер — `mini-messenger/server.js`**, запускается через `npm start` в корне
`mini-messenger`. Если снова понадобится что-то поменять на бэкенде — правьте только этот файл.

## Важно про Windows 7

Electron версии 23+ отказался от поддержки Windows 7/8.1. В `package.json` жёстко закреплена
версия **electron 22.3.27** — последняя официально работающая на Windows 7. Не поднимайте её выше
22.x, если поддержка Win7 нужна.

## Сборка .exe-установщика

Собирать нужно на Windows-машине (или через GitHub Actions с `windows-latest`):

```bash
cd desktop-client
npm install
npm run dist
```

Установщик появится в `desktop-client/dist/*.exe`, работает на 32- и 64-бит Windows (7, 8.1, 10).

**Иконка.** `build/icon.ico` (иконка приложения — .exe, ярлык на рабочем столе, панель задач) и
`tray-icon.png` (иконка в системном трее) уже готовы — речевой пузырь на фирменном градиенте
"аватарок" приложения с зелёной точкой "в сети" в углу. Если захотите заменить на логотип
организации: `build/icon.ico` нужен именно как многослойный .ico (несколько размеров внутри одного
файла — 16/24/32/48/64/128/256px, иначе Windows будет брать первый попавшийся размер и мылить
иконку на панели задач), `tray-icon.png` — обычный PNG 32×32.

## Проверить без сборки установщика

```bash
cd desktop-client
npm install
npm start
```

## Что умеет сейчас

**Роли.** Первый зарегистрированный пользователь автоматически становится админом.
Дальше роли (сотрудник / зам. начальника / начальник / администратор) назначает админ
через окно администрирования (значок-щит в шапке ростера — виден только админу). Изменения роли,
отдела или удаление пользователя применяются на других открытых клиентах сразу — сервер
рассылает уведомление по WebSocket, перезаходить в аккаунт не нужно.

**Отделы.** Админ создаёт отделы и распределяет по ним сотрудников в том же окне.
Ростер группирует контакты по отделам, показывает счётчик "в сети/всего" рядом с названием отдела
(в сети = активен или AFK), и позволяет свернуть отдел кликом по названию — состояние
сворачивания запоминается локально.

**Поиск по ростеру.** Просто начните печатать имя, пока окно ростера активно — вместо своего
профиля вверху появится строка поиска с мгновенной фильтрацией. Backspace до пустой строки или
Escape возвращают обычный вид.

**Рассылки / История рассылок.** Единая точка входа для всех — пункт "История рассылок" в самом
верху списка контактов (никакого отдельного значка в шапке ростера больше нет). У обычных
сотрудников это просто лента прошлых рассылок. У начальников, замов и админов там же, в шапке
открывшегося окна, есть кнопка "Написать" — по клику разворачивается форма отправки (кнопка
"нажимается" — подсвечивается, пока форма открыта, и гаснет при закрытии), точно так же, как
кнопка "История" открывает панель истории в окне чата.

**Тема оформления.** В "Настройках" — переключатель тёмная/светлая, применяется сразу ко всем
открытым окнам клиента без перезапуска.

**Чат.** Заголовок окна — статус-индикатор + имя + "Личная переписка" в одну компактную строку.
Время сообщения — в правом нижнем углу пузыря (как в большинстве мессенджеров), а не сверху слева.
Свой скроллбар в стиле клиента везде, где есть прокрутка.

**Чат "очищается" каждый день.** При обычном открытии окна чата показываются только сегодняшние
сообщения — но вся переписка остаётся на сервере. Кнопка-часы "История" в шапке чата открывает
панель: список дней с количеством сообщений (клик — открыть день) и полнотекстовый поиск по всей
истории переписки с этим человеком/комнатой.

**Администрирование — только через веб-панель на сервере.** В десктоп-клиенте окна администрирования
больше нет вообще — управление пользователями, отделами, ролями и файлами теперь исключительно
через веб-страницу сервера (см. `mini-messenger/README.md`), доступную только тем, у кого роль
"Администратор". Раньше в клиенте было две почти одинаковые панели администрирования (в Electron-
окне и на сервере), что уже приводило к путанице и багам из-за рассинхрона — теперь она одна.

**Профиль и настройки — по клику на своё имя.** В ростере строка с собственным именем (там же,
где раньше просто отображался "кто я") теперь кликабельна — открывает одно окно, где сразу и смена
отображаемого имени, и все настройки клиента, и выход из аккаунта. В шапке ростера остался только
значок "История рассылок" — он виден всем, доступ к самой отправке рассылок регулируется ролью уже
внутри этого окна.
- Смена отображаемого имени (не логина)
- Тема оформления (тёмная/светлая)
- Открывать окно чата при новых сообщениях (вместо системного уведомления)
- Порог статуса "Отошёл" — через сколько минут бездействия срабатывает AFK (по умолчанию 30)
- Запоминать размер окон между запусками
- Держать окна поверх остальных приложений
- Папка для сохранения файлов по умолчанию
- Выход из аккаунта — с подтверждением в теме клиента, а не системным диалогом Windows

**Отправка файлов.** Кнопка-скрепка в открытом чате, правый клик по контакту в ростере →
"Отправить файл…" (сработает, даже если чат ещё не открыт), либо просто перетащите файлы из
проводника прямо в окно чата — везде можно выбрать сразу несколько файлов за раз. После выбора
появляется окошко с двумя вариантами: **"Быстро"** — файлы уходят сразу как есть, либо
**"С подписью"** — можно написать текст, который отправится вместе с файлами. Все выбранные файлы
и подпись (если есть) — это одно сообщение и один пузырь в чате, а не россыпь отдельных, сколько
бы файлов вы ни выбрали за раз. Лимит на файл — 50 МБ, меняется в `MAX_UPLOAD_BYTES` в `server.js`.
Скачивание идёт через `webContents.downloadURL` в главном процессе (не обычной ссылкой) — так не
остаётся зависших пустых окон, а имя файла при сохранении всегда совпадает с тем, что отправили
(сервер отдаёт его через `Content-Disposition`, на диске файл лежит под техническим именем, но это
не видно пользователю). Папку для сохранения по умолчанию можно задать в настройках — тогда файл
сохраняется сразу туда, без диалога "Сохранить как". Во время скачивания иконка файла превращается
в кольцо прогресса с процентами внутри, а по завершении — в зелёную галочку на пару секунд (если
сервер не прислал размер файла, кольцо просто крутится без цифр — это тоже нормально).

**Развернуть на весь экран.** Кнопка-квадрат между свернуть и закрыть есть в каждом окне клиента,
иконка сама переключается между "развернуть"/"восстановить".

**Окно чата можно двигать за шапку** (имя собеседника, статус), не только за пустое место рядом.
Технический нюанс на будущее: `-webkit-app-region: drag` в Electron **не наследуется** дочерними
элементами — если добавляете новый текст в шапку и хотите таскать окно за него тоже, ставьте
`drag` явно на этот элемент, а не только на родителя (иначе выглядит как будто работает, а на
деле область не перетаскивается).

**История переписки — по месяцам, не плоским списком на год.** Открывается кнопкой "История" в
шапке чата. Слева — месяцы (самый свежий раскрыт, остальные свёрнуты, клик разворачивает), внутри
— дни с количеством сообщений. Сверху — постоянно доступный полнотекстовый поиск по всей истории
с этим человеком/комнатой: чтобы найти переписку годичной давности, обычно быстрее ввести
ключевое слово, чем листать месяцы вручную. Группировка дней учитывает часовой пояс конкретного
компьютера (передаётся на сервер параметром при каждом запросе) — корректно работает, даже если
сервер физически стоит в другом часовом поясе, чем сотрудники.

**Статусы присутствия.**
- зелёный — активен (реальная активность мыши/клавиатуры где угодно в системе, не только в мессенджере)
- жёлтый — отошёл (AFK), нет активности дольше порога
- серый — мессенджер не запущен

Порог AFK сейчас **временно уменьшен до 2 минут** (`IDLE_AFTER_SECONDS` в `main.js`) для тестирования
по просьбе — верните `30 * 60` перед тем, как раздавать сотрудникам в постоянную работу, иначе статус
будет срабатывать почти у всех, кто просто не двигает мышью пару минут (читает, думает над ответом).

При наведении на статус "Отошёл" — не просто "AFK", а сколько именно времени человек уже отошёл
(например, "Отошёл (7 мин назад)"), и то же самое при наведении на свой статус — с точностью до
секунд по факту простоя. Раньше был баг: если у пользователя открыто хотя бы одно окно чата, статус
"Отошёл" не наступал вообще — потому что окно чата держит своё собственное WebSocket-подключение к
серверу и раньше никогда не сообщало по нему свой статус, из-за чего сервер считал это подключение
вечно "активным" и это перекрывало настоящий AFK-статус от подключения ростера. Теперь каждое окно с
собственным WS-соединением (сейчас это только `chat.html`) обязательно пересылает статус бездействия
по своему соединению — если добавляете новое окно с собственным WS, не забудьте сделать то же самое.

**Важно про виртуальные машины:** если тестируете на ВМ (VMware/VirtualBox/Hyper-V) и статус не
переключается на AFK даже после ожидаемого времени бездействия — возможно, дело в интеграции мыши
между хостом и гостем: она может сама генерировать события движения курсора, которые Windows
засчитывает как активность. Это особенность ВМ, а не баг клиента — определение бездействия
использует стандартный Windows API (`GetLastInputInfo`) и на физическом ПК работает корректно. Если
хотите проверить на ВМ — попробуйте отключить "интеграцию мыши"/"seamless mode" на время теста.

Если один и тот же аккаунт открыт на нескольких компьютерах — при наведении на контакт
всплывающая подсказка покажет имена всех ПК, каждое на отдельной строке.

**Фоновая работа.** Закрытие окна ростера сворачивает приложение в системный трей, а не завершает
его — сообщения продолжают приходить. Выход — через пункт "Выход" в меню трея.

**Уведомления.** Новое личное сообщение, сообщение в общей комнате или рассылка — всплывающее
уведомление Windows. Клик по нему открывает нужный чат.

**Копирование и сохранение.** Текст сообщений и рассылок теперь выделяется и копируется как обычно
(раньше это было выключено глобально, чтобы случайный драг по интерфейсу не выделял всё подряд).
Правый клик по сообщению — "Копировать текст"; правый клик по прикреплённому файлу — "Сохранить как…"
с системным диалогом выбора места (это не то же самое, что папка по умолчанию в настройках — тут
разовый выбор конкретно для этого файла). В рассылках теперь тоже можно прикреплять файлы — точно
так же, как в обычном чате, с тем же диалогом просмотра перед отправкой.

## Как это работает
1. Сначала запустите центральный сервер: `cd .. && npm start`.
2. Адрес сервера "вшит" в клиент — правится в `desktop-client/config.js` (`SERVER_URL`), больше
   нигде. На экране входа поля для ручного ввода адреса нет специально — в организации
   предполагается только один сервер, поэтому после смены адреса нужно пересобрать `.exe`
   (`npm run dist`) и раздать заново. Достаточно логина и пароля для входа.
3. Двойной клик по контакту открывает отдельное окно чата — можно держать открытыми несколько
   одновременно. Правый клик по контакту — быстрое меню "Написать"/"Отправить файл".

## Общие файлы клиента
`renderer/theme.css` и `renderer/ui-kit.js` подключены на каждой странице и общие для всех окон:
- `theme.css` — переменные тёмной/светлой темы, общий стиль скроллбара, стили модальных окон.
- `ui-kit.js` — SVG-иконки вместо эмодзи (эмодзи не отображались в собранном .exe на части систем
  из-за отсутствия цветного эмодзи-шрифта — SVG рисуется одинаково всегда), `uiAlert`/`uiConfirm`
  вместо системных `alert`/`confirm`, применение и живое обновление темы.

Если добавляете новое окно — подключите оба файла тем же способом, что и в остальных `.html`.

**Осторожно с `-webkit-app-region: no-drag` + CSS `transition`.** Был баг: строки пользователей в
ростере начинали мигать (то подсвечены при наведении, то нет) с частотой в районе 8-10 раз в
секунду. Причина — на `.row` стояло `-webkit-app-region: no-drag` (совершенно не нужное, строка и
так никогда не была внутри перетаскиваемой зоны) одновременно с `transition: background .12s`.
Такое сочетание в Electron/Chromium может вызывать паразитный пересчёт drag-региона прямо во время
CSS-перехода, из-за чего элемент теряет и тут же снова получает hover-состояние по кругу. Вывод:
ставьте `no-drag` только на элементы, которые *реально* лежат внутри `-webkit-app-region: drag`
контейнера (шапка окна и то, что в ней) — и не смешивайте это с hover-переходами на этом же
элементе.

**Второй источник того же моргания (более редкий, раз в несколько секунд): полная пересборка
списка на каждое presence-сообщение.** `renderList()` делает `list.innerHTML = ''` и строит все
строки заново — а presence-сообщение от сервера приходит при изменении статуса **любого**
пользователя, не только того, над кем сейчас курсор. Если в этот момент мышь стоит над строкой,
браузер уничтожает наведённый DOM-узел и создаёт новый на его месте без :hover, — визуально это
тоже моргание, просто заметно более редкое, чем баг с `no-drag`+`transition` (raз в 2-8 секунд, а
не десяток раз в секунду). Поэтому `ws.onmessage` для `type: 'presence'` теперь вызывает не
`renderList()`, а лёгкую `updatePresenceOnly()`, которая точечно обновляет классы точек/тултипы/
счётчики в уже существующих `.row`/`.section`, не трогая сам DOM. `renderList()` (полная
пересборка) остаётся только для смены самого списка людей, поиска и сворачивания отделов — то
есть действий, где список объектов реально меняется, а не просто их статус.

## Формат сообщений с файлами (для тех, кто будет дорабатывать сервер)
В таблице `messages` файлы каждого сообщения хранятся в колонке `files_json` (JSON-массив
`[{url, name, size}, ...]`) — одно сообщение может нести произвольное число файлов, отсюда и
"один пузырь на одну отправку" в интерфейсе, сколько бы файлов пользователь ни выбрал разом.
Старые колонки `file_url`/`file_name`/`file_size` остались в схеме только для сообщений, которые
были отправлены до этого изменения (тогда сообщение могло нести максимум один файл) — их читает
функция `normalizeRow()` в `server.js`, которая приводит и старый, и новый форматы к единому виду
`files: [...]` перед отправкой клиенту. Если правите SQL-запросы к `messages` — не забудьте, что
почти каждая выборка проходит через `normalizeRow`/`.map(normalizeRow)`. Таблица `broadcasts`
устроена так же (своя колонка `files_json`, тоже через `normalizeRow`).

## Дальнейшие шаги
- HTTPS/WSS для сервера — обязательно перед боевым использованием вне локальной сети, иначе пароли
  и переписка идут в открытом виде. Загрузка/скачивание файлов сейчас тоже идёт по обычному http.
- Автозапуск при старте Windows и автообновление — через `nsis.runAfterFinish` и `electron-updater`.
