# Искра — десктоп-клиент (Windows)

Приложение для сотрудников: список контактов и отдельные окна чатов, как в Psi, но в современном
виде. Живёт в трее, сообщения приходят и когда окна закрыты. Работает на Windows 7, 8.1 и 10.

Сервер — отдельно, см. [`../mini-messenger/`](../mini-messenger/README.md). Клиент без него не работает.

## Запуск и сборка

Проверить без сборки установщика:

```bash
npm install
npm start
```

Собрать `.exe` (только на Windows или через GitHub Actions с `windows-latest`):

```bash
npm run dist          # результат — dist/*.exe, ставится на 32- и 64-бит Windows 7/8.1/10
```

**Адрес сервера** по умолчанию зашит в `config.js` (`SERVER_URL`) — меняйте там и пересобирайте
установщик. Пересборка ради смены адреса нужна не всегда: на экране входа по **Ctrl+S** открывается
скрытое поле ввода адреса, оно сохраняется в настройках этого компьютера и имеет приоритет над
`config.js`. Поле специально не на виду — это не то, что должен трогать рядовой сотрудник.

**Иконки.** `build/icon.ico` — приложение (ярлык, панель задач), `tray-icon.png` — трей. Если
меняете на логотип организации: `.ico` должен быть многослойным (16/24/32/48/64/128/256 px в одном
файле, иначе Windows возьмёт первый попавшийся размер и замылит иконку), `tray-icon.png` — обычный
PNG 32×32.

## Про Windows 7 — не поднимайте Electron выше 22

Electron 23 и новее отказался от Windows 7 и 8.1. В `package.json` жёстко закреплён
**electron 22.3.27** — последняя работающая версия. Если поддержка Win7 нужна, не повышайте её.

**Ускорение графики на Win7 отключено намеренно** (`app.disableHardwareAcceleration()` в начале
`main.js`, только при версии ядра «6.1»). Драйверы DirectX тех лет не рассчитаны на современный
Chromium и роняли приложение. На более новых Windows ускорение остаётся включённым — теряется
только плавность анимаций.

**Про краш `0x80000003` при выключении компьютера.** Он был вызван тем, что обработчик закрытия
окна списка контактов в обычной ситуации отменяет закрытие и прячет окно в трей — а во время
настоящего завершения сеанса Windows такой отказ ломает штатное завершение Chromium. Подробный
разбор всех трёх причин и того, как это устроено сейчас, — в комментарии к `beginShutdown()` в
`main.js`. Если будете трогать этот код, прочитайте комментарий целиком: там же объяснено, почему
уборку нельзя выполнять прямо внутри перехватчика оконных сообщений.

## Возможности

**Список контактов.** Люди сгруппированы по отделам, у каждого отдела счётчик «в сети/всего», отдел
сворачивается кликом. Чтобы найти человека, просто начните печатать имя — сверху появится строка
поиска. Escape возвращает обычный вид. Двойной клик открывает чат, правый клик — быстрое меню
«Написать» / «Отправить файл».

**Личные чаты, общая комната и группы.** Группу может собрать любой сотрудник под свою задачу:
кнопка «+» в разделе «Группы». Переименовать её, менять состав и удалить может создатель или
администратор; выйти самому можно всегда.

**Чат очищается каждый день — но ничего не теряется.** При открытии окна показаны только сегодняшние
сообщения. Кнопка-часы «История» в шапке открывает панель: месяцы → дни с количеством сообщений, и
полнотекстовый поиск по всей переписке с этим человеком или группой. Внутри дня старые сообщения
подгружаются по мере прокрутки вверх. Дни считаются по часовому поясу вашего компьютера, даже если
сервер стоит в другом.

**Ответы и реакции.** Наведите курсор на сообщение — над ним появится панелька: ответить или
поставить смайлик. Цитата в ответе сохраняется навсегда, даже если оригинал давно уехал вверх.

**«Печатает».** Пока собеседник набирает текст, внизу переписки появляется пузырёк с бегущими
точками.

**Отметки о прочтении.** У своих сообщений в личной переписке — галочка: серая, пока собеседник не
прочитал, синяя после. В группах и общей комнате галочек нет: там «прочитано» ни о чём не говорит.

**Непрочитанные.** На контактах и на «Объявлениях» — счётчик. Он переживает перезапуск клиента:
пропущенное, пока приложение было закрыто, сервер досчитывает при следующем входе.

**Объявления (рассылки).** Пункт в самом верху списка контактов, виден всем. У большинства это
просто лента объявлений; у кого есть право «Рассылки» — в шапке появляется кнопка «Написать».
К объявлению можно приложить файлы.

**Файлы.** Скрепка в чате, правый клик по контакту → «Отправить файл…» (работает, даже если чат
не открыт), либо перетаскивание прямо в окно. Можно выбрать сразу несколько — уйдут одним
сообщением, с подписью или без. Во время скачивания иконка превращается в кольцо с процентами, по
завершении — в зелёную галочку. Папку для сохранения можно задать в настройках, тогда файлы будут
складываться туда без вопросов. Максимальный размер и разрешённые типы задаёт администратор в
веб-панели сервера.

**Статусы.** Зелёный — за компьютером, жёлтый — отошёл, серый — мессенджер не запущен. Учитывается
реальная активность мыши и клавиатуры во всей системе, а не только в мессенджере. Через сколько
минут включается «Отошёл» — настраивается, по умолчанию 30. При наведении видно, как давно человек
отошёл, а если он работает с нескольких компьютеров — имена всех.

> На виртуальной машине статус «Отошёл» может не наступать: интеграция мыши между хостом и гостем
> сама генерирует движения курсора, и Windows считает это активностью. Это особенность ВМ, а не
> ошибка клиента — на обычном компьютере всё определяется правильно.

**Профиль и настройки** — клик по своему имени вверху, панель раскрывается прямо под ним:
отображаемое имя, тема (тёмная/светлая, применяется сразу во всех окнах), масштаб интерфейса,
открывать ли окно чата при новом сообщении, порог «Отошёл», запоминать размеры окон, держать окна
поверх остальных, папка для файлов, выход из аккаунта.

**Подсказка про Caps Lock** на экране входа — пароль не виден, и набранный с включённым Caps Lock он
выглядит точно так же, как правильный.

**Фоновая работа.** Закрытие окна списка контактов прячет приложение в трей, а не выключает его.
Полный выход — пункт «Выход» в меню трея.

**Администрирование только через веб-панель сервера.** В клиенте его нет намеренно: раньше было две
почти одинаковые панели, и они разъезжались между собой.

## Если будете дорабатывать

**Общие файлы окон.** `renderer/theme.css` (переменные тем, скроллбары, модальные окна) и
`renderer/ui-kit.js` (SVG-иконки, `uiAlert`/`uiConfirm`, применение темы, отправка ошибок на сервер)
подключены на каждой странице. Добавляете новое окно — подключите оба.

**Экранируйте всё, что пришло от людей.** Имя сотрудника он задаёт себе сам, и без `escapeHtml()`
оно попадает в разметку как код. Это уже приводило к настоящей уязвимости — см. историю коммитов.
`escapeHtml` экранирует и кавычки, поэтому годится и для значений внутри атрибутов.

**Эмодзи рисуются картинками, а не шрифтом.** На Windows 7 нет цветного эмодзи-шрифта. Текст
сообщений прогоняется через `window.emojiHtml()` (`ui-kit.js`), картинки лежат в `renderer/emoji/`
(графика Google Noto Emoji, лицензия MIT/Apache 2.0; эмодзи Apple использовать нельзя — они
проприетарные). Картинки есть **только** для набора из панели выбора (`EMOJI_LIST` в `chat.html`,
около 50 штук) — добавляете новый смайлик в список, положите рядом и его `.png` (имя файла — hex-код
символа, например `1f600.png`). Любой другой эмодзи просто останется текстовым символом. Отдельно
подключён чёрно-белый шрифт Noto Emoji (`renderer/fonts/`) — чтобы вместо пустых квадратов на Win7
было видно хоть что-то.

**Каждое окно чата держит своё соединение с сервером** и обязано само сообщать по нему статус
бездействия. Иначе сервер считает это соединение вечно активным, и статус «Отошёл» не наступает,
пока открыт хоть один чат. Делаете новое окно со своим соединением — не забудьте про это.

**Не смешивайте `-webkit-app-region: no-drag` с `transition` на одном элементе.** Такое сочетание
в Chromium вызывает пересчёт зоны перетаскивания прямо во время анимации, и элемент начинает мигать
при наведении по 8–10 раз в секунду. `no-drag` нужен только тому, что реально лежит внутри шапки окна.

**Не пересобирайте весь список на каждое сообщение о присутствии.** Оно приходит при смене статуса
любого сотрудника; если в этот момент пересоздать строки, элемент под курсором потеряет наведение и
список будет моргать. Для этого есть отдельная лёгкая `updatePresenceOnly()`; полная пересборка —
только когда действительно меняется состав списка.

**`-webkit-app-region: drag` не наследуется.** Добавили текст в шапку и хотите таскать окно за него
— поставьте `drag` на сам элемент, а не только на родителя.

**Файлы сообщения** хранятся в колонке `files_json` таблицы `messages` (массив `{url, name, size}`)
— одно сообщение несёт сколько угодно файлов. Старые колонки `file_url`/`file_name`/`file_size`
остались только ради сообщений, отправленных до этого изменения; и то и другое приводит к общему
виду `normalizeRow()` в `server.js`. Правите выборки из `messages` — помните, что почти все они
проходят через неё.
